WHAT IT MEANS
-------------

1. The website easily handles 200 visitors at the same time, with no failed
   requests and responses well under one second.

2. Full download time per file (median 0.38 s, 95% under 2.3 s) was limited
   mostly by the test computer's own internet connection, not by the website.
   Real visitors each use their own connection.

3. The real limit is monthly bandwidth, not speed. Each visit used about
   2.6 MB:
     - Vercel Hobby plan (100 GB a month):  about 38,000 visits a month
     - Vercel Pro plan (1 TB a month):      about 380,000 visits a month
   Videos use the most bandwidth.

4. This test itself used about 9.8 GB of the site's Vercel bandwidth.


HOW THE TEST WORKED
-------------------

Each simulated visitor:
  - opened the Home page (page, scripts, styles, font, images and the
    banner video),
  - then visited one or two more pages (About, Schedule, Speakers, a speaker
    page or Summit Archives), pausing 3-8 seconds between pages like a real
    person.
On Summit Archives, visitors also loaded gallery photos and video posters,
and one in four started a video (the first 1 MB, as a browser does when
"play" is pressed).

A separate steady stream of 2 small requests per second measured how quickly
the server answered as the load increased.

Limits of this test: it ran from one computer in India, so it does not show
speed from other countries or with thousands of visitors at once.


HOW TO RUN IT AGAIN
-------------------

  k6 run scripts/load-test.js                  full test (200 visitors, ~8 min, ~10 GB)
  k6 run -e PEAK=50 scripts/load-test.js       lighter test (50 visitors)
  k6 run -e SMOKE=1 scripts/load-test.js       quick 40-second check
